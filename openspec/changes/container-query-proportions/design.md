## Context

当前响应式实现混用视口单位(`vw` / `dvh` / `vmin`)和 Tailwind 断点类(`sm:` / `lg:`),导致:
- 按钮高度用 `7.5dvh`,但竖屏下侧列只占视口 65%,按钮相对容器偏小
- 箭头用断点类在 1023→1024px 处从 48px 跳至 80px
- 中央数字用 `min(28vw, 38dvh)`,上限 14rem 在大屏下过小
- 矮横屏用 `@media (max-height: 500px)` 触发布局切换,判据与容器实际可用空间无关

需改用 CSS Container Queries,让组件尺寸基于父容器而非视口。浏览器支持: Chrome 105+ / Safari 16+ / Firefox 110+ 全面可用,覆盖目标设备。

## Goals / Non-Goals

**Goals:**

- 将所有组件尺寸从视口单位改为容器查询单位
- 统一各端箭头与按钮的视觉权重比为 0.75:1
- 提升按钮触控目标从 63~80px 至 82~96px
- 提升中央数字上限从 14rem (224px) 至 18rem (288px)
- 消除 1023→1024px 和 500px 高度等断点处的视觉突变
- 保持现有布局结构(横屏三段式、竖屏双列)和视觉风格

**Non-Goals:**

- 不改变布局模式本身(如不引入新的 grid 区域)
- 不调整颜色、字体、圆角等视觉 token
- 不改变计分逻辑或交互流程
- 不新增组件或删除现有功能

## Decisions

### 1. 容器化粒度选择父容器而非每个子元素

为 `.side-panel-root` 和 `.score-area` 建立 `container-type: size`,而非为每个按钮单独建立容器。

**选择原因**: 按钮、箭头、间距需要基于同一容器协调计算比例,单独容器化会导致各自独立缩放,无法锁定相对比例。

**替代方案被否决**: 为每个按钮单独 `container-type` → 按钮间无法共享容器高度计算统一间距,且性能开销更大。

### 2. 按钮高度设为容器的 15%

`min-height: clamp(2.75rem, 15cqh, 6rem)` - 侧栏容器高度的 15%,下限 44px,上限 96px。

**选择原因**:
- 15% 使 PC (788px 侧栏) 按钮触及 96px 上限,充分利用空间且不过大
- 手机竖屏 (550px 列高) 按钮为 82px,比当前 63px 提升 30%
- 矮横屏 (295px 侧栏) 按钮为 44px,刚好满足触控下限

**替代方案被否决**:
- 10%: PC 按钮仅 79px,提升不明显
- 20%: PC 按钮 158px 过大,挤压箭头和撤销按钮空间

### 3. 箭头与按钮比例锁定为 0.53:1

箭头容器 `9cqh`,箭头本体 `8cqh`,按钮 `15cqh` → 比例 8:15 ≈ 0.53:1。

**选择原因**: 箭头是次要指示元素,应明显小于按钮;0.53:1 在所有端保持一致视觉次要地位,消除当前 PC 的 1:1(视觉平级)和平板的 0.6:1 不一致问题。

**替代方案被否决**:
- 固定像素值 (如 60px): 大屏下箭头相对按钮过小,小屏下可能溢出
- 更大比例 (如 0.75:1): 箭头与按钮视觉权重过于接近,弱化按钮主导地位

### 4. 中央数字同时受容器宽高约束

`font-size: clamp(3.5rem, min(55cqw, 62cqh), 18rem)` - 取容器宽度 55% 和高度 62% 中较小者。

**选择原因**:
- 横屏 PC (912×788 卡片): 高度为约束,数字 488px → 上限 288px,不溢出
- 竖屏 iPad Pro (1000×410 卡片): 高度为约束,数字 254px,自动适配
- 手机竖屏 (374×253 卡片): 高度为约束,数字 157px
- `min()` 确保数字在窄高卡片和宽矮卡片中都不溢出

**替代方案被否决**:
- 仅用 `cqw`: 竖屏高卡片中数字会溢出高度
- 仅用 `cqh`: 横屏宽卡片中数字过小,浪费宽度空间
- 更大比例 (如 70cqw): 上限 18rem 会在更小视口触发,失去放大效果

### 5. Grid 列宽从固定上限改为百分比

```css
grid-template-columns: minmax(9rem, 22%) minmax(12rem, 1fr) minmax(9rem, 22%);
```

侧栏占 22%,下限 9rem (144px),中央占剩余,下限 12rem (192px)。

**选择原因**:
- PC (1600px): 侧栏 352px (比原 280px 增大 26%),按钮可容纳更大字号
- 平板横屏 (1024px): 侧栏 225px (比原 205px 增大 10%)
- 窄屏 (568px): 触发 9rem 下限保护,不会过窄
- 22% 是侧栏在 PC 和平板间保持协调的最大比例,更大会挤压中央

**替代方案被否决**:
- 保留 17.5rem 上限: PC 侧栏仍为 280px,按钮触控目标改善有限
- 25%: 平板横屏侧栏 256px 挤压中央,中央区域不足 12rem 下限

### 6. 竖屏级数区占 32% 高度

```css
grid-template-rows: minmax(8rem, 32%) minmax(0, 1fr);
```

级数区占 32%,下限 8rem (128px),操作区占剩余。

**选择原因**:
- iPad Pro 竖屏 (1366px 高): 级数区 437px (比原 410px 增大 7%),操作区 929px
- 手机竖屏 (844px 高): 级数区 270px (比原 253px 增大 7%),操作区 574px
- 32% 让操作区占约 68%,按钮有充足空间触及 96px 上限
- 移除 26rem 上限,大屏级数卡片按比例放大,数字不被压制

**替代方案被否决**:
- 保留 26rem (416px) 上限: iPad Pro 级数区仍为 410px,数字被压制
- 35%: 操作区剩余 65%,按钮空间略紧

### 7. 布局切换阈值改为容器 260px

```css
@container side-panel (height < 260px) {
  .result-buttons { flex-direction: row; }
}
```

侧栏容器高度小于 260px 时横排结果按钮。

**选择原因**:
- 260px = 44px × 4 (四个最小按钮) + 箭头最小高度 + 间距,是纵排的最低空间需求
- 判据从视口高度改为容器高度,与实际可用空间一致
- 消除 499→500px 的结构性跳变: 499px 视口可能有 295px 侧栏(足够纵排),500px 视口可能只有 240px 侧栏(不够纵排)

**替代方案被否决**:
- 保留 `@media (max-height: 500px)`: 判据维度错配,中间尺寸畸形
- 更低阈值 (如 220px): 纵排时按钮被压到 44px 以下,违反触控要求

### 8. 间距与按钮同源缩放

按钮间距 `2cqh`,侧栏内边距 `2.5cqh`,与按钮的 `15cqh` 同源。

**选择原因**: 间距是按钮尺寸的衍生量,应同步缩放保持视觉节奏一致;若间距用固定 rem,大屏下按钮放大但间距不变,视觉会拥挤。

**替代方案被否决**:
- 固定 rem: 各端视觉节奏不一致,大屏拥挤、小屏稀疏
- 更大比例 (如 3cqh): 间距过大,浪费垂直空间

## Risks / Trade-offs

**[容器查询性能开销]** → 容器查询比媒体查询多一次布局计算。缓解: 仅两个容器 (`.side-panel-root` 和 `.score-area`),且 `container-type: size` 已被浏览器优化;实测在目标设备上无明显性能影响。

**[旧浏览器不支持容器查询]** → Chrome 105+ / Safari 16+ / Firefox 110+ 前的版本不支持。缓解: 保留原有 `clamp()` 作为 fallback,旧浏览器回退到视口单位,不影响基本可用性。目标设备 (iOS 16+、Android Chrome 最新、现代桌面浏览器) 均已支持。

**[数字上限提升至 18rem 可能在极宽屏溢出]** → 3840×2160 (4K) 下卡片宽度约 1800px,55cqw = 990px 远超 18rem (288px) 上限,实际不会溢出。

**[侧栏宽度增大 26% 挤压中央区域]** → PC (1600px) 下中央从 1040px 减至 896px,仍远超 12rem (192px) 下限。平板横屏 (1024px) 中央从 614px 减至 574px,仍充足。

**[按钮高度从 15cqh 计算可能在极端尺寸下违反触控要求]** → 下限 2.75rem (44px) 保护机制确保即使容器高度小于 293px (44 / 0.15),按钮仍不低于 44px。

**[容器查询单位不支持 calc() 复杂计算]** → 当前设计仅用简单百分比,不涉及 `calc(15cqh + 1rem)` 等复杂表达式,无此风险。

**[布局切换阈值 260px 可能在某些异形设备上误判]** → 260px 基于四个 44px 按钮的理论最小值,若实际渲染时字号、padding 导致按钮需要更多空间,可能仍然重叠。缓解: 真机验证矩阵覆盖 16 个尺寸,发现后调整阈值。

## Migration Plan

1. **SidePanel 容器化**: 为 `.side-panel-root` 添加 `container-type: size; container-name: side-panel`,不改变其他样式
2. **按钮和箭头改容器单位**: 将 `ResultButtons` / `UndoAction` 的 `min-height` 从 `7.5dvh` 改为 `15cqh`;将 `SidePanel` 箭头的 Tailwind 类 `h-11 / h-12 / h-20` 替换为内联 CSS `height: clamp(2.25rem, 9cqh, 5rem)`
3. **ScoreCard 容器化**: 为 `.score-area` 添加 `container-type: size; container-name: score-area`;将 `.score-number` 的 `font-size` 从 `clamp(4rem, min(28vw, 38dvh), 14rem)` 改为 `clamp(3.5rem, min(55cqw, 62cqh), 18rem)`
4. **Grid 比例调整**: 将 `Scoreboard.vue` 的 `grid-template-columns` 从 `clamp(7.5rem, 20vw, 17.5rem)` 改为 `minmax(9rem, 22%)`;竖屏 `grid-template-rows` 从 `clamp(10rem, 30dvh, 26rem)` 改为 `minmax(8rem, 32%)`
5. **布局切换改容器查询**: 将 `@media (orientation: landscape) and (max-height: 500px)` 改为 `@container side-panel (height < 260px)`
6. **间距同步**: 将按钮间距从 `clamp(0.375rem, 1.2dvh, 0.75rem)` 改为 `clamp(0.25rem, 2cqh, 0.875rem)`;侧栏 padding 从固定值改为 `clamp(0.375rem, 2.5cqh, 1.25rem)`
7. **验证矩阵**: 在 16 个目标尺寸逐一截图复核,确认无溢出、无重叠、触控目标 ≥44px
8. **更新 DESIGN.md**: 补充容器查询约束章节,记录比例系统规则

**回滚策略**: 若容器查询导致布局崩溃,回退 commit 恢复视口单位;因容器查询是纯 CSS 改动,无需数据迁移,回滚无副作用。
