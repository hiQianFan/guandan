# 响应式尺寸比例评估

## 问题描述

当前实现的响应式布局在三端(PC、平板、手机)都存在元素比例不协调的问题:

1. **操作按钮与视觉主体不匹配**: 侧栏操作区的按钮高度、箭头灯尺寸与中央级数卡片的大小不成比例
2. **触控目标偏小**: PC 和大屏平板上按钮相对整体界面占比过小,用户需要精确瞄准
3. **垂直空间利用不均**: 侧栏高度内留有大量空白,但按钮高度被固定上限压制
4. **断点处突变**: 在 1023px→1024px 和 500px 高度附近,元素尺寸出现视觉跳变
5. **多套单位混用**: vw(侧栏宽度)、dvh(按钮高度)、vmin(水印)、rem(中央数字)各自独立缩放,中间尺寸互不同步

## 具体尺寸测量

### PC 桌面 (1600×900)

**实际渲染值**:
- 侧栏宽度: `clamp(7.5rem, 20vw, 17.5rem)` → 280px (被上限锁定)
- 侧栏可用高度: 900 - (footer ~32) - (padding 40×2) ≈ 788px

**侧栏内部 (SidePanel)**:
- 箭头容器: `h-24` (lg断点) → 96px
- 箭头图标: `h-20 w-20` → 80px
- 结果按钮最小高度: `clamp(3.5rem, 7.5dvh, 5rem)` → 67.5px (900×0.075=67.5,被上限锁定为 80px)
- 按钮间距: `clamp(0.375rem, 1.2dvh, 0.75rem)` → 10.8px
- 撤销按钮高度: 同结果按钮 → 80px
- 垂直栈总高: 96 + (80×3 + 10.8×2) + 80 + gap ≈ 418px

**比例问题**:
- 侧栏 788px 高度,操作区仅占 ~53%,剩余 370px 为空白 padding
- 箭头 (80px) 与按钮 (80px) 几乎等高,视觉权重相当,但箭头应为次要指示元素
- 中央级数数字上限 14rem (224px),与侧栏总高比为 1:3.5,视觉主导地位不足

### 平板横屏 (1024×768)

**实际渲染值**:
- 侧栏宽度: `clamp(7.5rem, 20vw, 17.5rem)` → 204.8px (1024×0.2)
- 侧栏可用高度: 768 - footer - padding ≈ 668px

**侧栏内部**:
- 箭头容器: `h-14` (sm断点) → 56px
- 箭头图标: `h-12 w-12` → 48px
- 结果按钮: `clamp(3.5rem, 7.5dvh, 5rem)` → 57.6px (768×0.075)
- 按钮间距: ~9.2px
- 垂直栈总高: 56 + (57.6×3 + 9.2×2) + 57.6 + gap ≈ 314px

**问题**:
- 1023px→1024px 宽度跨越时,箭头从 `h-11`(44px) 跳至 `h-12`(48px),间距从 `gap-2`→`gap-3`
- 这是 Tailwind 断点 `sm:` (640px) 和 `lg:` (1024px) 分层造成的视觉突变
- 侧栏操作区仍只占 47% 高度,留白过多

### iPad Pro 竖屏 (1024×1366)

**布局切换**: 使用竖屏双列布局
- Grid 行: `clamp(10rem, 30dvh, 26rem)` (顶部级数) → 409.8px (1366×0.3)
- 剩余给下方红蓝列: 1366 - 409.8 - padding ≈ 916px

**每列内部**:
- 列宽: (1024 - gap - padding×2) / 2 ≈ 500px
- 箭头容器: `h-14` → 56px
- 结果按钮: `clamp(3.5rem, 7.5dvh, 5rem)` → 80px (1366×0.075 > 80,触顶)
- 垂直栈: 56 + (80×3 + gap) + 80 ≈ 422px

**问题**:
- 侧列高 916px,操作区仅 422px,占比 46%
- 按钮已触及 5rem 上限无法继续放大,但可用高度还很充裕
- 中央级数卡片高 409.8px,但数字本身被 14rem (224px) 锁死,卡片内大量留白
- 用户手指触达 500px 宽度内的 80px 按钮,相对整体界面显得偏小

### 手机竖屏 (390×844)

**布局**:
- 顶部级数行: `clamp(10rem, 30dvh, 26rem)` → 253.2px (844×0.3)
- 下方操作列高: 844 - 253.2 - footer - padding ≈ 550px

**每列内部**:
- 列宽: (390 - gap - padding) / 2 ≈ 187px
- 箭头容器: `h-11` → 44px
- 结果按钮: `clamp(3.5rem, 7.5dvh, 5rem)` → 63.3px (844×0.075)
- 垂直栈: 44 + (63.3×3 + gap) + 63.3 ≈ 309px

**问题**:
- 列高 550px,操作区 309px,占比 56%,比大屏设备略好但仍有改进空间
- 按钮高 63.3px 在窄列 (187px) 内占比合理,但字号 `clamp(1.25rem, min(3vw, 4dvh), 2rem)` → 1.25rem 触底,在宽屏设备上显得过小

### 矮横屏 (667×375, iPhone SE)

**布局**: 横屏三段式,但 height ≤ 500px 触发按钮横排模式

**实际渲染**:
- 侧栏宽度: `clamp(11rem, 31vw, 20rem)` → 206.77px (667×0.31)
- 侧栏高度: 375 - footer - padding ≈ 295px
- 结果按钮横排后: 每个宽 ~64px, 高 `min-height: 3.25rem` → 52px
- 撤销按钮: 宽度同侧栏,高 52px
- 垂直栈: 箭头44 + 结果行52 + 撤销52 + gap ≈ 172px

**问题**:
- 横排后按钮变为竖长条 (64×52),主副文字上下堆叠,字号被压缩至 `1.125rem` 和 `0.6875rem`
- 499px→500px 高度跨越时,布局从横排→纵排,按钮总占用空间从 ~172px 跳至 ~314px,是一个巨大的结构性突变
- 这个断点选择不合理,应基于实际内容能否放下,而非固定像素值

## 根本原因分析

### 1. 按钮尺寸基于全视口而非容器

当前按钮高度使用 `clamp(3.5rem, 7.5dvh, 5rem)`:
- `7.5dvh` 是视口高度的 7.5%,但在竖屏布局中,侧列实际只占视口高度的 ~65%
- 导致按钮相对于**容器可用空间**偏小,但相对于**视口**已触顶
- iPad Pro 竖屏 1366px 高度下,按钮早在 1067px 就触及 5rem 上限,即使列高还有 916px

**应该**: 按钮尺寸基于父容器 `.side-panel-root` 的实际高度,而非全视口

### 2. 多套单位体系互不同步

- 侧栏宽度: `20vw` (视口宽度百分比)
- 按钮高度: `7.5dvh` (视口高度百分比)
- 中央数字: `28vw` 或 `14rem` (视口宽度或固定rem)
- 箭头图标: Tailwind 固定类 `h-11 / h-12 / h-20` (断点跳变)
- 水印字号: `16vmin` (视口最小维度)

这些单位在不同屏幕比例下缩放速率完全不同:
- 16:9 桌面 (1600×900): vw 快, dvh 慢
- 4:3 平板 (1024×768): vw 与 dvh 接近
- 竖屏手机 (390×844): dvh 快, vw 慢

导致同一组件在不同设备上的视觉权重比例波动极大。

### 3. Tailwind 断点造成离散跳变

箭头图标从 `h-11` (44px) 跳至 `h-12` (48px) 再跳至 `h-20` (80px),分别发生在 `sm:` (640px) 和 `lg:` (1024px) 断点。

这种固定断点无法适应:
- 1024×600 上网本: 触发 `lg:` 得到 80px 箭头,但高度只有 600px,箭头挤压按钮
- 1023×1200 窄高屏: 只得到 48px 箭头,但空间充裕
- 断点基于宽度,而箭头挤压的是高度,判据维度错配

### 4. 中央级数上限与容器脱钩

`font-size: clamp(4rem, min(28vw, 38dvh), 14rem)`:
- 14rem = 224px 上限在 1600px 宽、900px 高的桌面上明显偏小
- 卡片本身可用空间 (912×788) 远大于数字所需
- 竖屏 iPad Pro 卡片高 410px,数字 224px,占 55%,卡片内留白 45%

**应该**: 数字尺寸基于卡片自身尺寸 (container query units) 而非视口

### 5. 矮横屏断点是结构性硬切换

`max-height: 500px` 触发按钮横排:
- 499px → 纵排 (总需 ~314px)
- 500px → 横排 (总需 ~172px)
- 1px 变化导致 142px 空间需求差异

在 480~560px 高度区间的设备 (如某些 Android 横屏、分屏窗口) 会出现:
- 500px 以下横排但空间其实够纵排,浪费可用高度
- 501px 纵排但实际挤压,按钮被压到最小值

## 改进方案

### 方案核心: 容器查询 + 统一比例系统

将所有尺寸从"视口驱动"改为"容器驱动",使用 CSS Container Queries (`cqh` / `cqw` / `cqmin`)。

**优势**:
- 组件尺寸与其实际可用空间挂钩,布局切换时自动重新计算
- 消除竖屏/横屏下同一组件比例失衡问题
- 中间尺寸平滑过渡,无断点跳变

**浏览器支持**: Container Queries 在 Chrome 105+、Safari 16+、Firefox 110+ 全面可用,覆盖目标设备。

### 具体调整

#### 1. SidePanel 建立容器上下文

```css
.side-panel-root {
  container-type: size;
  container-name: side-panel;
}
```

按钮尺寸改为基于容器高度:

```css
.result-button {
  /* 侧栏高度的 15%,下限 44px 触控要求,上限 96px 避免过大 */
  min-height: clamp(2.75rem, 15cqh, 6rem);
}
```

在 PC (侧栏 788px) 下: 788×0.15 = 118px → 触及 96px 上限
在 iPad Pro 竖屏 (列高 916px) 下: 916×0.15 = 137px → 96px
在手机竖屏 (列高 550px) 下: 550×0.15 = 82.5px
在矮横屏 (侧栏 295px) 下: 295×0.15 = 44.25px

按钮从 63~80px 提升至 82~96px,触控体验显著改善,且各端比例一致。

#### 2. 箭头尺寸容器化

替换 Tailwind 断点类为容器查询:

```css
.arrow-slot {
  height: clamp(2.25rem, 9cqh, 5rem);
}
.arrow-wrapper {
  width: clamp(2rem, 8cqh, 4.5rem);
  height: clamp(2rem, 8cqh, 4.5rem);
}
```

箭头与按钮的高度比锁定在 8:15 ≈ 0.53,在所有端保持一致的视觉次要地位。

#### 3. 中央卡片数字容器化

```css
.score-area { container-type: size; container-name: score-area; }

.score-number {
  /* 同时受容器宽高约束,取较小者 */
  font-size: clamp(3.5rem, min(55cqw, 62cqh), 18rem);
}
```

PC (912×788): min(501, 488) = 488px → 上限 288px (18rem)
iPad Pro 竖屏 (1000×410): min(550, 254) = 254px
手机竖屏 (374×253): min(206, 157) = 157px

数字上限从 224px 提升至 288px,PC 上主视觉地位更明确;竖屏下自动受高度约束不溢出。

#### 4. 矮横屏断点改为内容驱动

将硬性 `max-height: 500px` 改为基于容器实际能否容纳纵排:

```css
/* 侧栏容器高度不足以纵排四个 44px 按钮 + 箭头 + 间距时横排 */
@container side-panel (height < 260px) {
  .result-buttons { flex-direction: row; }
}
```

260px = 44×4 (四个最小按钮) + 间距 + 箭头最小高度的临界值。

这样:
- 375px 高矮横屏: 侧栏 295px > 260px → 纵排,但按钮压缩至 44px 仍可用
- 320px 高极矮屏: 侧栏 ~240px < 260px → 横排
- 判据从"视口高度"改为"容器能否放下",消除结构性跳变

#### 5. 统一间距比例

所有间距改为容器高度百分比:

```css
.result-buttons { gap: clamp(0.25rem, 2cqh, 0.875rem); }
.side-panel-root { padding: clamp(0.375rem, 2.5cqh, 1.25rem); }
```

间距与按钮尺寸同源缩放,保持视觉节奏一致。

#### 6. Grid 列宽改为比例驱动

```css
.scoreboard-layout {
  /* 侧栏占 22%,中央占剩余,但侧栏有绝对上下限 */
  grid-template-columns:
    minmax(9rem, 22%) minmax(12rem, 1fr) minmax(9rem, 22%);
}
```

PC (1600px): 侧栏 352px (比原 280px 增大 26%)
平板横屏 (1024px): 侧栏 225px (比原 205px 增大 10%)

侧栏加宽后按钮可容纳更大字号,触达面积增加。

#### 7. 竖屏顶部行改为比例分配

```css
@media (orientation: portrait) {
  .scoreboard-layout {
    /* 级数区占 32%,操作区占 68%,不使用 clamp 硬上限 */
    grid-template-rows: minmax(8rem, 32%) minmax(0, 1fr);
  }
}
```

iPad Pro 竖屏: 级数区 437px (原 410px),操作区 929px
手机竖屏: 级数区 270px (原 253px),操作区 574px

移除 26rem 上限,让大屏设备的级数卡片按比例放大。
