## Context

计分器是单页 Vue 3 应用，主要在牌桌旁的手机、平板和电脑上使用。当前桌面/平板三段式结构、深色红蓝视觉和左右箭头黄灯已获得认可，但 `vw`、`vh`、`vmin` 与 `sm/md/lg` 尺寸叠加后，对窄屏和矮屏不稳健；手机竖屏目前被旋转提示完全阻断。操作流为选择结果后确认，左右各有确认/撤销，小屏还会把三个结果按钮横向压缩。

## Goals / Non-Goals

**Goals:**

- 保持现有颜色、字体、圆角、中央级数和红蓝对称关系。
- 让手机竖屏、手机横屏、平板和桌面都能完成计分与撤销。
- 缩短高频操作为一次点击，并让牌桌两侧都可就近撤销。
- 用结构化布局和最小尺寸约束替代相互冲突的视口尺寸。
- 达到 WCAG 2.2 AA 的键盘、焦点、对比度、触控目标和减少动画要求。

**Non-Goals:**

- 不重新设计品牌或引入新的视觉风格。
- 不增加 Toast、确认弹窗、操作锁或新的说明区域。
- 不改变升级、过 A、历史回退等计分规则。
- 不删除现有左右箭头黄灯，也不增加文字贡牌关系、关系条或说明区。

## Decisions

### 1. 结果按钮直接提交一局

`useGameControl` 暴露单个 `recordRound(winner, result)` 操作，按顺序保存快照、计算级数、更新打级方并清理不再需要的临时状态。结果按钮直接调用该操作。

选择后再确认被否决：它增加一次点击和更长的触达距离，而历史回退已经提供低成本纠错。

### 2. 两侧保留同一全局撤销入口

红蓝操作区各渲染一个“撤销上一局”按钮，均调用 `undoRound()`。撤销与结果按钮同宽同高并占据完整一行，但以中性描边和较低视觉权重与计分按钮区分。重复的是入口而不是状态或逻辑，目的是让牌桌两边的人都能触达。

只在中央放一个撤销入口被否决：在大屏和平板上会增加跨屏伸手距离。

### 3. 布局按可用空间分为两种结构

- 899px 及以下的窄竖屏（含手机与竖屏平板）：顶部为中央级数，下方红蓝双列操作区；每列纵排 `+3 / +2 / +1 / 撤销上一局`，不显示旋转遮罩。
- 其余尺寸：保留红侧栏、中央级数、蓝侧栏三段式；每个侧栏继续纵排同一四行操作栈。

布局容器使用 CSS media/container query、`minmax()`、`clamp()` 和明确的最小触控尺寸。高度来自父容器剩余空间，不再由中央组件单独声明 `80vh`。视觉断点只负责页面结构切换；结果按钮不再在小屏切换为横排，因此各端保持相同的操作顺序和肌肉记忆。

### 4. 保留箭头黄灯，拒绝文字贡牌区

保留当前左右箭头黄灯的状态、位置与语义。ImageGen 概念稿中的“贡牌关系”标题、文字关系条和额外说明区不进入实现；不因本提案删除现有贡牌状态数据。

### 5. 无障碍反馈复用现有状态

所有交互使用原生 `button`，焦点在操作后保持不变。当前级数与打级方使用一个现有可见区域作为 `aria-live="polite"` 状态源，不新增可见提示文案。红蓝区域有可访问名称，状态同时用文字/图标表达，不能只依赖颜色。

键盘按 Tab 顺序访问所有结果和撤销按钮，Enter/Space 使用原生按钮行为；不新增全局单键快捷键，避免牌桌环境和浏览器快捷键冲突。

### 6. `DESIGN.md` 记录现状而非提出改版

根设计文档从实际 CSS 和组件提取颜色、字体、圆角、间距与组件状态，并把本提案的响应式、触控和无障碍规则写入既有六段格式。后续 UI 优化必须在这些约束内进行。

## Risks / Trade-offs

- [误触会立即改变比分] → 两侧始终提供可见且可用的撤销入口，并保留完整历史回退。
- [竖屏双列在极窄设备上文字拥挤] → 以 44px 为硬下限，优先减少外围间距和装饰，不缩小触控目标或关键文字。
- [两个撤销按钮可能被理解为各自撤销] → 两者统一命名“撤销上一局”，可访问名称也明确其全局作用。
- [删除临时状态会波及现有类型] → 先按调用链移除 UI，再由类型检查确认可删除范围。

## Migration Plan

1. 先改为原子 `recordRound` 并更新最小逻辑检查，确保直接计分与撤销闭环正确。
2. 删除确认路径，将两侧撤销扩展为与结果按钮同尺寸，并统一四行纵向操作栈。
3. 重排窄竖屏与三段式布局，统一尺寸 token。
4. 补充语义、焦点和减少动画规则，在目标视口进行键盘与触控验证。
5. 生成 `DESIGN.md` 并更新 README。若需回滚，可恢复旧操作组件和布局提交；历史数据结构不需要迁移。
